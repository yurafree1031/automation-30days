# ヒアリングシート（想定）

デモ用に、「よくある会社」を想定して埋めたもの。実際の案件では、お客様と一緒に埋める。
「（想定）」は、デモのために置いた仮の回答。お客様ごとに必ず確かめる。作りは、この想定に合わせている。

## 1. 会社と業務

| 項目 | 回答 |
|---|---|
| 業種・従業員数 | 飲食店を2〜3店舗、従業員20〜40名（想定） |
| 自動化したい業務（今の手順を順番に） | ①お客様が、レシートのQRコードからGoogleフォームのアンケートに答える → ②店長が週に1回、回答シートを開いて満足度の平均や選択肢の件数を数える → ③結果を表にまとめて、オーナーと各店長にメールで送る |
| その業務にかかっている時間・頻度・件数 | 週50〜150件の回答（想定）。集計とメール作りに週30分〜1時間。忙しい週は集計が抜ける |
| 自動化したあとの理想の状態 | 毎週月曜の朝に、先週の集計がメールで届く。誰も集計しなくてよい。週ごとの平均の移り変わりが、シートで見られる |

## 2. 使う人と管理する人

| 項目 | 回答 |
|---|---|
| 毎日使う人（部署・人数・ITへの慣れ） | オーナーと各店長の3〜5名。届いたメールを読むだけ。ITには詳しくない（想定） |
| 管理する人（設定の変更・トラブル対応をする人）はいるか | 本部の事務の人が兼任（想定）。専任のIT担当はいない |
| 担当者が替わる可能性（異動・引き継ぎ・パートなど） | あり（店長の異動）。送り先は「設定」シートを書き換えるだけで変えられるようにする |
| 使う端末（パソコン／スマートフォン） | 集計のメールは、スマートフォンのGmailで読む。設定の変更はパソコン |

## 3. 今の環境

| 項目 | 回答 |
|---|---|
| Google Workspace（会社のアカウント）か、個人のGoogleアカウントか | 個人のGoogleアカウント（想定）。メールの送信は1日100人まで（`ノウハウ/GASの上限.md`）。週1回・5人なら足りる |
| ツールを動かすアカウント（担当者が替わっても残る、会社のアカウント） | 会社の共用アカウント（想定）。「送信を始める」を押した人のGmailから送られるので、個人のアカウントで押さない |
| すでに使っているフォルダ・シート・ファイルの形式 | すでにGoogleフォームでアンケートを取っていて、回答はスプレッドシートにたまっている。フォームと回答のシートはそのまま使う |
| 一緒に使っている他のツール（会計ソフト・チャット・メールなど） | Gmail（想定） |
| 他のツールに取り込むときに必要な項目 | なし |

## 4. 会社の決まり（作り方が変わるところ）

| 項目 | 回答 |
|---|---|
| 業務の決まり（例：勘定科目の一覧、取引先ごとの扱い、承認の流れ） | 集計するのは、フォームの質問そのまま（ユーザーに確認済み）。段階評価は平均と点数ごとの件数、選択式は選択肢ごとの件数と割合、記述式は記入の件数だけ（中身はシートで見る。ユーザーに確認済み）。名前など集計しない質問は、「集計する質問」シートで外せる |
| 集計の期間と送る時 | 初めは毎週月曜9時に、前の週（月〜日）の分を送る。「設定」シートで毎日・毎月、曜日、時刻を変えられる（ユーザーに確認済み）。いつまで送るかは、フォームの締め切り（受付のオフ・締め切りの日時）で決まる。受付が終わったら最後の分を送って終わる。「1回だけ」は、受付が終わったときに全部をまとめて送る（日付をツールに二重に設定させない。ユーザー指摘） |
| 移り変わりの見せ方 | 「推移のグラフ」シートに、集計している記述式以外の質問を全部出す。段階評価は平均を1つの折れ線、選択式・複数選択は質問ごとに割合の積み上げ棒、ほかに回答数の棒。メールには載せない（ユーザー指摘） |
| 決算月（年度の始まり。集計を年度・四半期で見るとき） | 使わない（週・月の集計だけ） |
| データの名前の付け方・保存場所の決まり | 集計の結果は「集計の履歴」シートに、期間ごとに1行ずつ残す（ユーザーに確認済み） |
| 例外になるケースと、その扱い | 回答が0件の期間も「0件」と送る。届かないと、止まっているのか0件なのかが分からないため（ユーザーに確認済み）。送れなかった期間は、履歴に赤い行で残し、直ったら自動で送り直す。送信を止めていた間の期間は、再開のときに期間の数を見せて、送るかどうかを選んでもらう（ユーザーに確認済み。さかのぼるのは5期間まで） |
