# ヒアリングシート（想定）

デモ用に、「よくある会社」を想定して埋めたもの。実際の案件では、お客様と一緒に埋める。
「（想定）」は、デモのために置いた仮の回答。お客様ごとに必ず確かめる。作りは、この想定に合わせている。

## 1. 会社と業務

| 項目 | 回答 |
|---|---|
| 業種・従業員数 | 店舗・サービス業、従業員10〜30名（想定） |
| 自動化したい業務（今の手順を順番に） | ①ホームページの問い合わせフォーム（Googleフォーム）に回答が届く → ②事務の人がときどき回答シートを開いて気づく → ③内容を見て、担当者に口頭かメールで伝える → ④対応したかどうかは、それぞれの記憶とメールで管理 |
| その業務にかかっている時間・頻度・件数 | 月30〜100件（想定）。気づくまで半日〜1日かかることがあり、返事の漏れが年に数回ある |
| 自動化したあとの理想の状態 | 届いた瞬間に担当者のスマホにメールが届き、お客様とのやり取りが始まる。手を付けていない問い合わせは、忘れないように知らせる |

## 2. 使う人と管理する人

| 項目 | 回答 |
|---|---|
| 毎日使う人（部署・人数・ITへの慣れ） | 各担当者3〜5名（メールを受け取り、一覧の状態を変える）。ITには詳しくない（想定） |
| 管理する人（設定の変更・トラブル対応をする人）はいるか | 総務の担当者が兼任（想定）。専任のIT担当はいない |
| 担当者が替わる可能性（異動・引き継ぎ・パートなど） | あり。担当者の追加・変更は「担当者」シートを書き換えるだけでできるようにする |
| 使う端末（パソコン／スマートフォン） | 通知はスマートフォンのGmailで受け取る。一覧の状態の変更は、パソコンかスマートフォンのスプレッドシートアプリ |

## 3. 今の環境

| 項目 | 回答 |
|---|---|
| Google Workspace（会社のアカウント）か、個人のGoogleアカウントか | 個人のGoogleアカウント（想定）。メールの送信は1日100人まで（`ノウハウ/GASの上限.md`）。月100件・1件に1〜2人なら足りる |
| ツールを動かすアカウント（担当者が替わっても残る、会社のアカウント） | 会社の共用アカウント（想定）。「通知を始める」を押した人のGmailから通知が送られるので、個人のアカウントで押さない |
| すでに使っているフォルダ・シート・ファイルの形式 | すでにGoogleフォームを使っていて、回答はスプレッドシートにたまっている。フォームとその回答シートはそのまま使い、管理用の「問い合わせ一覧」を別に作る |
| 一緒に使っている他のツール（会計ソフト・チャット・メールなど） | Gmail（想定）。チャットツールは使っていない |
| 他のツールに取り込むときに必要な項目 | なし |

## 4. 会社の決まり（作り方が変わるところ）

| 項目 | 回答 |
|---|---|
| 業務の決まり（例：勘定科目の一覧、取引先ごとの扱い、承認の流れ） | 問い合わせの種類ごとに担当者が決まっている（想定）→「担当者」シートで、種類ごとに知らせる人を決める。どれにも当てはまらないときは「（それ以外）」の人へ |
| 決算月（年度の始まり） | 使わない（集計はしない） |
| データの名前の付け方・保存場所の決まり | 対応の状態は「未対応・対応済み」の2つ。管理するのは「やり取りを始めたか」だけで、終わったかは管理しない（ユーザーに確認済み）。受付番号は1からの通し番号 |
| 忘れを防ぐ決まり | 未対応のまま3日を過ぎたものを、毎週月曜9時に担当者ごとにリマインド。管理者には件数（ユーザーに確認済み） |
| 例外になるケースと、その扱い | 担当者が決まらない・メールを送れない問い合わせは、一覧に赤い行で残し、直したら送り直せるようにする。「通知を始める」より前に届いていた回答は、一覧に取り込まない（ユーザーに確認済み） |

## 5. AIとデータの扱い

| 項目 | 回答 |
|---|---|
| AIを使ってよいか、社外に送ってよいデータの範囲 | AIは使わない |
| 個人情報・機密情報が含まれるか | お客様の名前・メールアドレス・電話番号・問い合わせ内容。通知メールに全文を載せる（ユーザーに確認済み。社内の担当者だけに届く） |
