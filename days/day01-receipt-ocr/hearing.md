# Day 1 ヒアリングシート（想定）

30日デモ用に、「よくある会社」を想定して埋めたもの。実際の案件では、お客様と一緒に埋める。
「（想定）」は、デモのために置いた仮の回答。お客様ごとに必ず確かめる。作りは、この想定に合わせている。

## 1. 会社と業務

| 項目 | 回答 |
|---|---|
| 業種・従業員数 | 小売・サービス業、従業員10〜30名（想定） |
| 自動化したい業務（今の手順を順番に） | ①領収書・レシートを受け取る → ②日付・店名・金額を見ながら経費表に手入力 → ③勘定科目を自分で判断して入力 → ④月末に勘定科目ごとに集計 |
| その業務にかかっている時間・頻度・件数 | 月50〜100枚。1枚1〜2分で、月に1〜3時間。月末の集計にさらに1時間ほど（想定） |
| 自動化したあとの理想の状態 | 領収書の写真をフォルダに入れて、ボタンを1回押すだけ。経費表が埋まり、集計はグラフで見られる |

## 2. 使う人と管理する人

| 項目 | 回答 |
|---|---|
| 毎日使う人（部署・人数・ITへの慣れ） | 経理・総務の事務担当1〜2名。ITには詳しくない（想定） |
| 管理する人（設定の変更・トラブル対応をする人）はいるか | 総務の担当者が兼任（想定）。専任のIT担当はいない |
| 担当者が替わる可能性（異動・引き継ぎ・パートなど） | あり（異動・パート）。説明書がなくても、画面だけで使えるようにする |
| 使う端末（パソコン／スマートフォン） | ボタンの操作はパソコン。写真を撮ってフォルダに入れるのはスマートフォン |

## 3. 今の環境

| 項目 | 回答 |
|---|---|
| Google Workspace（会社のアカウント）か、個人のGoogleアカウントか | Google Workspace（想定）。共有ドライブのフォルダも使える作りにしてある |
| すでに使っているフォルダ・シート・ファイルの形式 | 領収書の写真（JPG・PNG）とPDFを、すでにドライブのフォルダに入れている。未処理と処理済みを分けたフォルダを、既存のものから指定する |
| 一緒に使っている他のツール（会計ソフト・チャット・メールなど） | 会計ソフトに、経費表をCSVで取り込む（想定）。連携はこのデモでは作らない |
| 他のツールに取り込むときに必要な項目 | 未確認。お客様に聞く（インボイスの登録番号・税率ごとの金額・税抜の金額が要るか。要るなら経費表の列を足す） |

## 4. 会社の決まり（作り方が変わるところ）

| 項目 | 回答 |
|---|---|
| 業務の決まり（例：勘定科目の一覧、取引先ごとの扱い、承認の流れ） | 勘定科目の一覧は会社で決まっている → 設定シートで変えられる（13個まで）。店ごとに勘定科目が決まっている店がある → 店別勘定科目シートで、AIの判断より優先して登録する（勘定科目は候補から選ぶ）。承認の流れはなし |
| 決算月（年度の始まり） | 3月決算・4月始まり（想定）。設定シートの「年度の始まりの月」で変えられ、グラフの年度別・四半期別はこれで数える |
| データの名前の付け方・保存場所の決まり | 画像は処理済みフォルダへ移す。ファイル名は変えない。経費表の画像列から元の画像を開けるようにする |
| 例外になるケースと、その扱い | 読み取れない写真（不鮮明・切れている・領収書でない）は、赤い行で残して手入力か撮り直し。確認が必要なもの（自信度が低い・日付が不自然・重複）は黄色い行 |

## 5. AIとデータの扱い

| 項目 | 回答 |
|---|---|
| AIを使ってよいか、社外に送ってよいデータの範囲 | 領収書の画像をAIに送ってよい（想定）。社外に出せない書類を扱うときは、有料のAPIキーを使う |
| APIキーを会社で用意できるか（費用は会社持ち） | 用意できる（想定）。使うたびに費用がかかるので、安いモデルを初期値にしてある。100枚あたり50円前後（料金表からの見積もり。精度テストで実測して直す） |
| 個人情報・機密情報が含まれるか | 領収書の店名・金額・日付のみ（想定）。宛名は読み取る項目にしていない。ただし、画像そのものはAIに送られる |
| AIの結果を、誰がどう確かめるか | 経理担当が、赤・黄色の行を、画像のリンクから見比べて確かめる。金額は特に確認する。AIの結果は、確認するまで確定扱いにしない |
